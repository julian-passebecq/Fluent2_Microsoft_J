## Pass 2 — grouping semantics and validated lessons

Add a pure local `src/figures/core/aggregation.ts`. Reuse `TableData`/row contracts and existing validation or semantic snapshot helpers where appropriate. Keep the existing general table compiler intact. The allowed contract is deliberately bounded:

| Contract | Required behavior |
| --- | --- |
| Input | One `TableData`, one grouping column, nonempty spec ID, and named aggregate definitions |
| Operators | `countRows` for `COUNT(*)`, `countNonNull` for a specified column, `sum` for a numeric column |
| Output | Groups with stable IDs, typed key values, contributing source row IDs, aggregate values, and deterministic display order |
| Identity | Based on spec ID, grouping column and typed key value; never first row/index or aggregate result |
| Display order | First encounter of each key, explicitly a teaching presentation order; SQL needs ORDER BY to promise row ordering |
| Numeric scope | Finite JavaScript numbers; tiny integer example amounts. Reject nonnumeric SUM input and non-finite inputs/results. No decimal/currency precision promises |
| NULL amount | Remains a source/group member, contributes to COUNT(*), contributes nothing to COUNT(amount) or SUM; all-null group SUM is null |
| NULL key | All null grouping keys form one group; NULL differs from the string `"null"` |
| Empty input | Zero groups when grouping by a column; no synthetic group. Global aggregation without a grouping column is unsupported |
| Validation | Reject duplicate/empty IDs, unknown group/aggregate columns, missing required row cells, unsupported aggregate kind, duplicate aggregate output IDs and output-name collisions |
| Purity | No input mutation, timers, DOM, randomness or formatting-based key comparison |

## Authoritative semantic reference

COUNT distinguishes all rows from non-null inputs; SUM ignores null inputs and returns null when it has no non-null inputs. The lesson implements only the bounded grouping subset specified here. [PostgreSQL aggregate documentation](https://www.postgresql.org/docs/current/functions-aggregate.html), checked 2026-09-08. The finite-number teaching contract is not a claim to emulate PostgreSQL numeric types or its query planner.
